# Pokédex: an OpenAPI importer over `async.query`

A tech demo, `examples/pokedex`, that browses [PokéAPI](https://pokeapi.co)
on every target, written against types and calls an `openapi:` import
generates from PokéAPI's own spec. The example is the reason; what it leaves
behind is the shape every data source takes -- **a component that brackets a
request with `effect`**, which the OpenAPI importer generates first and gRPC,
SQL and the rest generate next.

```sngl
import poke "openapi:./pokeapi.yml"

component detail(name string) ui.node {
    var mon option[poke.Pokemon] = null
    var loading = false
    var failure option[async.Failure] = null

    // asks again whenever name changes; the last answer stays while it does
    poke.pokemonRetrieve(id=name, :value=mon, :pending=loading, :failure=failure)

    if mon == null && loading {
        ui.spinner()
    }
    if failure != null {
        ui.text(value="Could not load {name}: {failure.message}")
    }
    if mon != null {
        ui.image { ui.remote(url=mon.sprites.frontDefault) }
        for var t = mon.types { ui.badge(text=t.type.name) }
    }
}
```

## The example

- A `nav.stack` of two pages: a paged list (`/`) and a detail page
  (`/pokemon/{name}`) whose params are a struct, as `nav.page` takes them.
- The list keys its request on `offset`, and a "More" button appends the
  page that arrives to a `var` (`@load`).
- The detail page shows the sprite through `ui.remote`, the types as badges,
  base stats as bars, and the evolution chain as links to other detail pages
  -- a second request keyed on the first's answer, which is a query under
  `if mon != null`.
- A card per Pokémon on the list, each its own query keyed on its name:
  the instance is the key, so nothing caches per argument.
- A search box filtering the loaded names; no endpoint searches.
- Builds for html (`--lang none`), fyne, gtk4, bubbletea and android. A target
  that cannot is a refusal with a position, recorded here, not a skip.
- The spec is vendored (`examples/pokedex/pokeapi.yml`), so a build is
  offline and reproducible. PokéAPI publishes it at the root of its
  repository (`openapi.yml`, OpenAPI 3.1, generated by drf-spectacular, its one
  server `https://pokeapi.co`); note the commit it
  was taken from beside it.

## Payload enums

`async.Result` is either a value or a failure, never both and never neither,
and a struct of two options cannot say so: reading the value after testing
the failure is a fact about two fields together, which narrowing does not
know. gRPC's `oneof` and an OpenAPI `oneOf` with a discriminator are the same
shape. So the first step is a type that holds exactly one of several things.

Go's proposal for one, golang/go#76920, is a declaration like a struct where
only one field is populated -- `type Maybe[T any] union { Unset atom; Set T }` -- and SNGL's `enum` is already its case where every variant is an atom.
So it is the enum, extended rather than a new kind:

```sngl
enum Direction { north, south, east, west }   // unchanged

enum Result[T any] {
    ok T
    failed Failure
}
```

- **A member may carry a type**, its payload; one that carries none is what
  every member is today. An enum takes type parameters
  (`EnumDecl = kw_enum [ ident ] [ TypeParams ] lbrace …`,
  `EnumMember = ident [ Type ] [ assign Expr ]`), and a member with a payload
  takes no `= value`.
- **Constructed as a struct literal naming one member**:
  `Result[Pokemon]{ok=mon}`, or `{ok=mon}` where the type is expected, as a
  struct literal's is; naming two is an error. A member with no payload is
  written as it is today, `Direction.north`.
- **Read by a selector**, as Go's two-value form reads it: `r.ok` is an
  `option[T]`, present only when that member is the one held, so the existing
  narrowing does the rest (`if r.ok != null { … r.ok … }`); a member with no
  payload reads as a `bool`.
- **Matched by member, binding the payload**: `match r { ok(var v) { … } failed(var f) { … } }`. Exhaustive as every match is, so an arm per
  member or an `else`. This is the binding pattern the match work deferred
  "until there is a use beyond unwrapping an option"; this is that use.
- **The zero value is the first member's**, with its payload's zero, as Go's
  proposal says, which is why a member a program means as a default goes
  first.
- **Comparable where every payload is**, so one may key an effect.
- **Each target**: an all-atom enum is emitted as it is today. With a
  payload, Go a struct of a tag and a field per payload member (comparable
  with `==`, its zero the first member's), Kotlin a sealed class of a data
  class per payload member and a data object per atom, JavaScript
  `{tag, value}` compared by a helper as a multi-base unit is, and the
  interpreter a value holding its member and payload. Go and Kotlin copy a
  generic one per instantiation as they do a struct.
- **JSON** reads one externally tagged, `{"ok": …}`, and a member with no
  payload as its name; `json.identifier` marks a member as it marks a field.
  An OpenAPI `oneOf` with a `discriminator` is a different layout, and maps
  once there is a spec that wants it.
- **Out of scope**: making `option[T]` one, which is #275.

## `async.query`: the shape

`sngl:remote` was a three-state box (`Value[T]`) and a query store keyed by
id and argument list, deleted in 7f6d6764b as superseded by `effect` and
ordinary async functions. This is that replacement, written down, and it goes
in `sngl:async` rather than a package of its own: `start` hands work off,
`do` brings the answer back, and `query` is the two bracketed by the tree --
the same subject, one level up. What it keeps from the box is the three
independent facts -- the last value, the last failure, an attempt in flight
-- and the failure classification; what it drops is the box type, the store,
and every lowering that knew about them. `lib/async/doc.sngl` grows a section
for it.

```sngl
// A request bracketed by the tree: asked when the node mounts and whenever
// `on` changes, abandoned when it unmounts. `fetch` is the adapter's call.
component query[K any, T any, F any](
    on K,
    fetch func(K) Result[T],
    :value option[T] = null,       // the last answer; kept through a refresh and a failure
    :pending bool = false,         // an attempt in flight
    :failure option[Failure] = null, // how the last attempt failed; cleared by a success
    @load(value T),
    @fail(f Failure),
) F {
    var attempt = 0

    effect(
        on = on,
        @mount(k) {
            attempt += 1
            var mine = attempt
            pending = true
            var r = fetch(k)
            if mine != attempt { return }   // a later key asked since: latest wins
            pending = false
            match r {
                ok(var v) {
                    value = v
                    failure = null
                    load(v)
                }
                failed(var f) {
                    failure = f
                    fail(f)
                }
            }
        },
        @unmount(k) { attempt += 1 },       // an answer after unmount lands nowhere
    )
}

func query.refresh(q query) { … }
```

- **Ordinary SNGL over `effect`**, like each target's `time.timer` override:
  no `#[builtin]`, no intrinsic, no pass. The two-way props are cells the
  call site binds or leaves to `passImplicitState`, so a program reads what it
  binds and nothing else.
- **A failure is a value, not a raise.** A screen renders it beside the
  stale value it still has, which a boundary cannot. A program that wants the
  boundary raises from `@fail`.
- **`Failure` comes back** as it was: `kind`, `message` and the adapter's own
  `code` (an HTTP status, a SQLSTATE, a gRPC status name), with `FailureKind`
  `transport`, `timeout`, `auth`, `request`, `server`, `decode`. `cancelled`
  goes: a superseded or unmounted attempt now writes nothing, so no screen
  can see one.
- **An adapter returns its failure; it does not raise it.** `fetch` answers
  `Result[T]`, a success carrying either the value or the `Failure` -- a 404
  is a response that arrived, and the request did not fail to run. So `error`
  stays as it is, the code travels in the value, and `query` catches nothing:
  a raise out of `fetch` is a bug in the adapter and reaches the nearest
  boundary like any other. `Result[T]` is the payload enum above,
  `{ ok T, failed Failure }`.
- **`refresh`** re-asks without a change of key: a retry button, a poll from
  a `timer`. Keyed on `{key=on, n=refreshes}`, a struct of comparable fields,
  so the effect re-mounts. Keeps the value, sets `pending`.
- **An adapter is a component over `async.query`.** The importer writes one
  per read operation, whose props are the operation's parameters and whose
  body is one `async.query(on={…params}, fetch=…, …)` handing its own two-way
  props through. gRPC's unary reads, a SQL query keyed on its arguments, a
  GraphQL query: each the same component over a different `fetch`. A write is
  not a query -- it is a plain async function a handler calls.
- **`query` is the one ordinary component in `sngl:async`**, beside two
  intrinsics. It is portable SNGL, so no target answers it; what a target
  answers is `start` and `do`, which the async `@mount` reaches through
  `passAsyncOffload`.

### What it needs from the language

Each is general, and each is a fixture of its own before `async.query` lands.

- **A func type that may be async.** `checkAsyncRules`' rule 3 is deferred
  because `ir.FuncSig` carries no colour, so handing an async
  function to `fetch` is invisible to `passAsyncOffload`, and the effect's
  `@mount` is not coloured async. Give the signature the flag rule 3 asks for.
- **An async `@mount` that writes state after it waits.** A handler may call
  an async function already; the writes after the wait have to reach the
  drawing thread (`async.do` on fyne and gtk4, nothing on html, a coroutine on
  the main dispatcher on android), and the writes in a library body reach
  reactivity through the instance's cells.
- **A library component with state, built at run time.** `async.query` under a
  `for` or a reactive `if` is an instance per copy. "Nothing emits a library
  body as one" is noted under the window's override; check it holds for a
  library component with a var, or make it.
- **A generic two-way prop**, `:value option[T]`, bound at a call site whose
  `T` is the adapter's.
- **bubbletea** answers no `async.do` (#272): the answer has to come back
  through `Update` as a `tea.Cmd`. Until then an `async.query` there is refused at
  the call.
- **The interpreter** runs `fetch` at mount, synchronously, and again when
  `on` changes, so `sngl test` is deterministic: a test reads `pending` as
  false and the answer as there.

## The `openapi:` scheme

A library plugin at `lib/x/scheme/openapi`, served like `c:` and `gir:` with
no import. `internal/imports.ParseScheme` already names `openapi3:` as the
example of a URI carrying a URI; the scheme is `openapi`, and the version is
read off the document.

- **Parsing is a build intrinsic answered in Go**, `openapi.parse`, the shape
  of `md.parse` and `gir.widgets`: it hands the handler typed SNGL data
  (`Spec`, `Schema`, `Field`, `Operation`, `Param`), never a dynamic value,
  and the handler writes the source with `out.write`. YAML and JSON both.
- **Where the spec comes from.** A path reads through the project FS with no
  grant, as `md:` does. A URL is a fetch from a host the repository chose, so
  it goes through the `NetGate` a `git:`/`http:` import asks, and is recorded
  by content digest so the store replays it; that needs a recorded network
  read in `sngl:x/gen`, which does not exist yet. The file form first.
- **Schemas to declarations.** An object is a struct; `enum` of strings an
  enum; a property not `required`, or `nullable`, an `option[T]`; `array` a
  `list[T]`; `additionalProperties` a `map[string, V]`; `$ref` the named
  declaration; `allOf` its fields merged. `integer` by `format` (`int32`,
  `int64`), `number` a `float`, `date`/`date-time` `time.date`/`datetime`.
  A 3.1 null union is an `option[T]` too, in both spellings the spec uses:
  `type: [integer, 'null']` (61 in PokéAPI's) and `oneOf: [$ref, {type: 'null'}]` (all six of its `oneOf`s, none of them anything else, and no
  `anyOf` or `discriminator`). A `oneOf` with a `discriminator` is a payload
  enum once JSON reads that layout; any other `oneOf`, and every `anyOf`,
  leaves the operation or field reaching it out and the import says so,
  rather than typed `any`.
- **Names.** A JSON key becomes a camelCase field (`front_default` →
  `frontDefault`) carrying `#[json.identifier("front_default")]` (see *JSON*), which is what
  the decoders read. A schema name that collides after conversion, or a
  reserved word, is renamed and the rename is reported once.
- **Operations.** Each is an async function answering `async.Result`, named by `operationId`
  (`pokemonRetrieveCall`), path parameters required, query parameters with
  their spec default or as `option`s, a body last. Each `GET` is also the
  adapter component over `async.query` (`pokemonRetrieve`), its props the
  parameters and its two-way props the query's, handed through. The component
  takes the bare `operationId` because it is what a view writes; the function
  is for handlers.
- **The server is a context**, `poke.server`, defaulting to the spec's first
  `servers` entry: dynamically scoped, so a test provides a local server with
  `t.setContext(poke.server, …)` and a program may point a subtree at a
  mirror.
- **Fixtures**: a trimmed spec in `testdata/openapi_*.txtar` with a golden of
  the written package (through the scheme store), and an `error_openapi_*`
  for each refused construct.

### What it writes

For two of PokéAPI's operations, abridged:

```sngl
// Code generated by the openapi: scheme from pokeapi.yml. DO NOT EDIT.

import async "sngl:async"
import http "sngl:http"
import json "sngl:json"

// Where the API is: the spec's first server. Provide another to point a
// subtree, or a test, somewhere else.
context #server("https://pokeapi.co")

struct NamedAPIResource {
    name string
    url  string
}

struct PaginatedPokemonSummaryList {
    count    int
    next     option[string]
    previous option[string]
    results  list[PokemonSummary]
}

struct PokemonSummary {
    name string
    url  string
}

struct Pokemon {
    id             int
    name           string
    #[json.identifier("base_experience")]
    baseExperience option[int]
    height         int
    weight         int
    sprites        PokemonSprites
    types          list[PokemonType]
    stats          list[PokemonStat]
}

struct PokemonSprites {
    #[json.identifier("front_default")]
    frontDefault option[string]
    #[json.identifier("front_shiny")]
    frontShiny   option[string]
}

struct PokemonType {
    slot int
    type NamedAPIResource
}

struct PokemonStat {
    #[json.identifier("base_stat")]
    baseStat int
    effort   int
    stat     NamedAPIResource
}

// GET /api/v2/pokemon/
//
// A page of Pokémon names, `limit` at a time from `offset`.
func pokemonListCall(limit option[int] = null, offset option[int] = null) async.Result[PaginatedPokemonSummaryList] {
    return getJSON[PaginatedPokemonSummaryList](
        url="{server}/api/v2/pokemon/",
        query={limit=limit, offset=offset},
    )
}

// GET /api/v2/pokemon/{id}/
//
// One Pokémon, by its number or its name.
func pokemonRetrieveCall(id string) async.Result[Pokemon] {
    return getJSON[Pokemon](url="{server}/api/v2/pokemon/{http.pathEscape(id)}/")
}

// GET /api/v2/pokemon/, asked again whenever limit or offset changes.
component pokemonList[F any](
    limit option[int] = null,
    offset option[int] = null,
    :value option[PaginatedPokemonSummaryList] = null,
    :pending bool = false,
    :failure option[async.Failure] = null,
    @load(value PaginatedPokemonSummaryList),
    @fail(f async.Failure),
) F {
    async.query(
        on={limit=limit, offset=offset},
        fetch=func(k struct { limit option[int], offset option[int] }) => pokemonListCall(limit=k.limit, offset=k.offset),
        :value=value,
        :pending=pending,
        :failure=failure,
        @load { load() },
        @fail { fail() },
    )
}

// GET /api/v2/pokemon/{id}/, asked again whenever id changes.
component pokemonRetrieve[F any](
    id string,
    :value option[Pokemon] = null,
    :pending bool = false,
    :failure option[async.Failure] = null,
    @load(value Pokemon),
    @fail(f async.Failure),
) F {
    async.query(
        on=id,
        fetch=pokemonRetrieveCall,
        :value=value,
        :pending=pending,
        :failure=failure,
        @load { load() },
        @fail { fail() },
    )
}
```

- **The key is the parameters**: one parameter is the key itself and its
  function is `fetch`; several are an anonymous struct, which compares field
  by field, and a lambda spreads it back out.
- **`query` is a struct**, as `sngl:http` takes one: a field per query
  parameter, named as the spec names it, and a declared struct with
  `#[http.identifier("…")]` on the fields whose spec name is no SNGL
  identifier.
- **`getJSON` is the package's own**, written once per generated package
  (see *What the generated package composes*), so the example's calls name it
  bare.
- **`server` is read at the call**, so a context provided around a component
  reaches the request it makes; a test provides a local server.
- **The component's family is `F`**, as `effect`'s and `timer`'s are: it
  renders nothing, so it goes in a layout, a canvas or a menu alike.
- A field named for a keyword (`type` here) is renamed only where SNGL's own
  grammar refuses it; a target's reserved word is `passReservedNames`'
  business and not the importer's.

## HTTP and JSON while the program runs

Nothing in `lib/` makes a request today, and nothing decodes JSON into a
declared type. The generated functions need both, and neither is OpenAPI's,
so each is a package of its own: `sngl:http` the transport, `sngl:json` the
encoding. Neither knows the other; the generated package composes them.

### `sngl:http`

The primitives for a call, and the vocabulary of the URL it is made to.

```sngl
enum Method { get, head, post, put, patch, delete }

struct Response {
    status  int
    headers map[string, string]
    body    string
}

// Sends one request. Answers a failure only where no response arrived --
// `transport` or `timeout`; a 404 is a response, and its status is read off it.
#[marks.intrinsic("http.send")]
func send[Q struct {} = struct {}](
    method Method,
    url string,
    query Q = Q{},
    headers map[string, string] = {},
    body option[string] = null,
) async.Result[Response]

func get[Q struct {} = struct {}](url string, query Q = Q{}) async.Result[Response] {
    return send(method=Method.get, url=url, query=query)
}

// The response, for a 2xx; otherwise the failure its status says: 401/403
// `auth`, other 4xx `request`, 5xx `server`, the status as the code. SNGL, not
// an intrinsic, so every target classifies alike.
func Response.checked() async.Result[Response] { … }

#[marks.intrinsic("http.pathEscape")]
const func pathEscape(segment string) string
```

- **A query is a struct**, a field per parameter, as a translation's
  arguments are for `i18n.format` (`[A struct {}]`): a `null` option is left
  off the URL, a list repeats the key, a scalar is spelled as `string(v)`
  spells it. The key is the field's SNGL name, or **`#[http.identifier("page-size")]`**
  where the wire name is not one -- the counterpart of `json.identifier`, and
  recorded on the IR field the same way. The struct is declared where it
  needs a mark (`struct PokemonListQuery`), since an anonymous literal has no
  field to carry one, and anonymous where it does not.
- **`send` is answered on the language axis**: Go `net/http`, JavaScript
  `fetch`, Kotlin `HttpURLConnection` on a coroutine, the interpreter Go's
  `net/http`. Each catches every host exception inside the intrinsic and
  answers `transport` or `timeout`, and each encodes the query from the
  struct's fields and their marks -- Go and Kotlin from the copy
  `passMonomorphize` made for `Q`, JavaScript and the interpreter off the
  value.
- **What is left for later**: other parameter locations (a header, a cookie),
  a request body type beyond `string`, streaming, a timeout setting, and
  credentials. A spec needing one leaves the operation out and says so.

### What the generated package composes

One function per generated package, written by the importer rather than
shipped, since it is the only place that knows both halves:

```sngl
func getJSON[T any, Q struct {} = struct {}](url string, query Q = Q{}) async.Result[T] {
    match http.get(url=url, query=query) {
        failed(var f) => {failed=f}
        ok(var r) => match r.checked() {
            failed(var f) => {failed=f}
            ok(var r) => json.decode[T](r.body)
        }
    }
}
```

### JSON

A field's name on the wire is a fact about the format, not about the field,
so it is a mark of the format's own package: `sngl:json`'s
`#[json.identifier("base_experience")]` on a struct field or an enum member, and no
mark means the SNGL name. Not `#[foreign]`: that says a declaration *is* a
host identifier, which a JSON key is not, and a struct may carry both. A
field keeps its SNGL name in the IR and on every host, and is read by
spelling as it is today; only the encoding asks the mark.

- **The mark is data on the IR field**, as `Foreign` is: the checker's handler
  records it (`ir.StructField.JSON`, or whatever shape the next format's mark
  wants beside it), and nothing reads it but an encoder.
- **Each language spells it its own way**, the way it spells a native: Go a
  `json:"base_experience"` struct tag on the field it emits (`,omitempty` on
  an option); Kotlin `@SerialName("base_experience")` on a `@Serializable`
  class; JavaScript, which has no annotation, a per-type rename the decoder
  applies; the interpreter reads the mark directly. A language with no way to
  spell one refuses a struct carrying it where `json.decode` reaches it.
- **Encoding is `sngl:json`'s too**: `json.decode[T](text) async.Result[T]` and
  `json.encode[T](v) string`, intrinsics on the language axis. A program
  reading a JSON file uses the same two, and the generated `getJSON` is
  `http.get` followed by `json.decode`.
- **Types**: an option is a key that may be absent or `null`; `datetime` and
  `time.date` are RFC 3339 strings; a unit, a func or a component has no JSON
  and is refused at the `decode`/`encode` that reaches it.
- **The next formats follow it**: a gRPC importer writes `#[proto.field(3)]`,
  a SQL one `#[sql.column("created_at")]`, each its package's mark, each
  spelled by the languages that answer its encoder.

- **android** needs the `INTERNET` permission in the manifest, only for a
  program that reaches the package.
- **Images** are already `ui.remote`, except that android draws nothing for
  one (no loader shipped). The demo wants that fixed or the detail page is
  blank there.

## Working this plan

Each step is one session, started on that step's branch, which carries this
file.

1. **Start**: check out the step's branch and merge `origin/main` into it (a
   merge, never a rebase). The first step whose row is not marked done is
   this session's.
2. **Work**: fixture first, as CLAUDE.md says; keep the CLAUDE.md section for
   what the step adds current as it goes. Install `githooks/pre-commit` if it
   is not, and do not edit the tree while `go tool verify` runs.
3. **Finish**, once the step is done and `go tool verify` passes:
   1. Mark the step's row done in this file (`✓` in the `#` column), noting
      anything it left for a later step under that step's section, and
      commit.
   2. Create the next step's branch from this one: `git switch -c <next branch>`, then `git switch -` back. The next step depends on this one, so it
      starts from it rather than from `main`; once this step's MR merges, the
      next session's merge of `origin/main` takes it in.
   3. On this step's branch, `git rm TODO.md`, commit ("Drop the plan from
      the branch"), push, and open the MR against `main`. CI refuses an MR
      that still carries `TODO.md`.
   4. Hand back the MR link and the next branch's name.
